# Always-on context

What sits in context every session — a `CLAUDE.md`, an imported rule file —
holds prohibitions; a procedure defers to its trigger.

**A prohibition is front-loaded** when it guards against something the agent
would otherwise do unprompted: nothing downstream discloses it in time.

**A procedure resident in context reads as a process to run.** Handed a recipe
before its moment, the agent performs it as ceremony, and a happy path meant to
be seamless grows steps. Put the recipe where its trigger fires — a skill whose
description names the moment, a hook, the gate's own output.

**A gate that emits its own instructions is invoked, not pre-satisfied.** Its
refusal *is* the report: it carries the format, the path and the next command.
Triggering it costs one call; reconstructing its demands by hand costs several
and still gets details wrong. So always-on text names the gate, not what the
gate would ask for.

That holds for a gate that is cheap, reversible and self-describing. It is no
licence to fire a destructive command and read the error.
