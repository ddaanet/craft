## Findings

### 1. SOURCE_FACTS is missing the fact this range absorbed. Proposed: medium

- **Where:** `scripts/check-skills.py:46-72`. This contradicts
  docs/design.md:183-185 (D-4, the other reviewer's path).
- **What:** `guardrail-must-permit-real-commands` was retired into
  test-discipline's coverage-shape.md:58-69 in this range. The ddaanet tier
  commit is "Retire guardrail-must-permit-real-commands into
  craft:test-discipline". Its slug was never added to `SOURCE_FACTS`. The
  precedent `reference-audit-after-a-move` was added when it was absorbed.
- **Failure scenario:** a later edit cites `guardrail-must-permit-real-commands`
  or its `.md` in a skill body. `private-reference` matches only listed slugs,
  so the gate passes and the shipped body points at a file no consumer has.
  FR-4's check silently passes. D-4 says "one absorbed into a skill after
  release" are listed, and now two have been absorbed.
- **Fix:** add the slug to `SOURCE_FACTS`. Update D-4's count, or better, drop
  the count from D-4 so it stops going stale, per shared rule "a fix lists cases
  only when the list is closed".

### 2. The split signal is still a line threshold next to a byte cap. Proposed: medium

- **Where:** `skills/plan-contracts/references/contracts-and-size.md:13-20`. The
  same rule is repeated in SKILL.md:43-44 and code-in-a-plan.md:53.
- **What:** line 13 says split when a task's contract "runs past ~400 lines",
  stated as the rule, not as an observation. Line 19 says split when it is
  "approaching the size cap", which line 5 defines as 20000 bytes for a whole
  file. Neither line converts between the two units.
- **Failure scenario:** a reviewer sizing one task gets two thresholds. One is
  in lines, which this range retired. The other is the whole-file byte cap.
  Applying the second literally, a single task must be about a full plan's cap
  before it splits. At the observed 3.5x ratio that means about 70 KB of
  implementation against a 20000-byte PR cap, so the signal fires far past the
  point it exists to catch.
- **Fix:** state the threshold once, in bytes. For example: "a single task's
  contract that would by itself fill a good share of a file's cap". Keep
  "~400-line contract producing a 1385-line implementation" as the dated
  measured instance. Make line 13 read as that observation, not as the rule.

### 3. "Exemption" is offered for an over-cap plan, and check-size refuses it. Proposed: medium

- **Where:** `skills/plan-contracts/references/contracts-and-size.md:55`. The
  same promise is repeated at line 77 ("before reaching for a split or an
  exemption").
- **What:** "An over-cap plan has two sanctioned escapes, a split and an
  exemption." The node names `check-size` at line 42, so the exemption reads as
  a `size.exempt` entry. check-size always skips root plans/ as a built-in and
  refuses an entry for it.
- **Probe:** in a scratch copy of the repo, I wrote
  `plans/2026-10-15-brief-guardrail-must-permit-real-commands.md # long plan`
  into `size.exempt` and ran `bash plugin-dev/check-size.sh`. It printed
  `size.exempt:1: plans/... — a built-in is always skipped` and exited 1.
- **Failure scenario:** an agent with a long plan follows the node, adds the
  exemption, and turns a green gate red. It also contradicts line 7 of the same
  node, which says the cap is soft for plans and needs no gate escape.
- **Fix:** for plans, the escapes are a split or a bounded overage, which is the
  soft-cap judgment at lines 109-120. Reserve `size.exempt` for files the gate
  counts. Reword both sentences.

### 4. The test-module docstring claims coverage the checker no longer has. Proposed: medium

- **Where:** `tests/test_check_skills.py:3`.
- **What:** "The checker pins every requirement in `docs/design.md`". FR-5 (size
  caps) moved to `check-size` in 9b8fcdc, so this is now contradicted by the
  checker's own docstring (scripts/check-skills.py:10-11).
- **Failure scenario:** a maintainer treats this suite as FR-5's cover and
  expects a size regression to fail here. Nothing in it exercises size.
- **Fix:** "pins the FR-4/FR-6 hygiene requirements …", or "every requirement it
  owns". Avoid restating a list.
