## Findings

### 1. FR-5's skip list is not closed, and a probe contradicts it. Proposed: medium

- **Where:** `docs/design.md:45-46`.
- **What:** FR-5 now says 20000 "for any other file outside `plans/` and the
  vendored `plugin-dev/`". `is_builtin` (`plugin-dev/check-size.sh:70-80`) also
  skips `uv.lock` and `package-lock.json` at any depth, and the scan skips
  binaries, symlinks and unreadable files. Probe: `wc -c uv.lock` is 48269, and
  `check-size` passes. The part A finding chose to leave lockfiles out, which is
  the open list the shared rule warns against.
- **Failure scenario:** a maintainer reads FR-5, sees `uv.lock` at 48 KB, and
  either concludes the gate is broken or adds a `size.exempt` entry for it,
  which `check-size.sh:132-133` refuses ("a built-in is always skipped") and
  turns the gate red.
- **Fix:** state the rule, not the list, the same way CLAUDE.md now does: "20000
  for any other file `check-size` scans". Drop the enumeration.

### 2. "None of it compresses" keeps the claim finding A4 dropped. Proposed: medium

- **Where:**
  `skills/design-doc-writing/references/splitting-an-oversized-doc.md:51`.
- **What:** the fix deleted "Rewording returns almost nothing" but kept the
  clause it elaborated, "and none of it compresses", in the same sentence. The
  same section then names levers that compress exactly that material: rewording
  each conclusion to fit one wrapped line (:57-62), collapsing restatements
  (:63), and moving argument out of conclusion bullets (:68-77).
- **Failure scenario:** the one A4 named. An author at the floor reads "none of
  it compresses", skips the concision levers, and makes a structural cut earlier
  than needed.
- **Fix:** end the sentence at "one line per rejected alternative." and drop
  "and none of it compresses". The "budget by measuring" sentence stays.

### 3. CLAUDE.md says "tracked", and the gate also scans untracked files. Proposed: medium (borderline)

- **Where:** `CLAUDE.md:7`.
- **What:** "any other tracked file `check-size` scans". The scan lists
  `git ls-files -z -co --exclude-standard` (`plugin-dev/check-size.sh:64`), so
  untracked, non-ignored files are counted too. The primary source contradicts
  the claim.
- **Failure scenario:** an agent leaves an untracked scratch or report file over
  20000 bytes outside `plans/`, trusting that only tracked files are capped.
  `just precommit` fails with `oversized-file` on a file unrelated to the staged
  change. The failure is loud, so triage may call this low.
- **Fix:** drop "tracked": "any other file `check-size` scans at 20000".

### 4. "`size.exempt` is not one of them" is stated for all plans. Proposed: medium (borderline)

- **Where:** `skills/plan-contracts/references/contracts-and-size.md:55-59`
  (shipped skill).
- **What:** the sentence rules out `size.exempt` as an escape for an over-cap
  plan, with the reason that `check-size` skips root `plans/`. A consumer whose
  plans live elsewhere, e.g. `docs/superpowers/plans/` (the superpowers
  writing-plans default, which `code-in-a-plan.md` discusses), has them counted
  by the gate. A cohesive plan kept a little over the cap as :111-116 allows
  then fails `check-size`. The clause "it is for files the gate counts" covers
  this case, but the sentence's subject says a plan never takes an entry.
- **Failure scenario:** that reader follows "not one of them", and is left with
  a split or shaving prose. The node forbids shaving prose.
- **Fix:** scope the exclusion to where it holds: "Under root `plans/` a
  `size.exempt` entry is not one of them: `check-size` skips that directory and
  refuses an entry there." Leave the counted-elsewhere case unstated rather than
  adding a rule for it.
